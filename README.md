# FieldLedger 农业观测账本

支持站点目录、修订采集、隔离复核、窗口统计、质量检查和带血缘的数据导出。观测按来源、站点、指标、时刻定位；来源优先级和质量状态会影响统计结果。

## 运行环境

使用 Node.js 22，核心功能依赖标准库。演示和测试只使用本地合成数据，不需要账户、设备或外部运行服务。请从项目根目录执行命令。

## 检查与运行

构建检查验证语法，测试使用临时数据目录，不会连接远端服务。

```sh
npm run build
npm test
npm run acceptance
```

演示会展示产品的实际数据处理和输出，运行结束自行退出。查看现有接口：

```sh
node src/cli.js help
```

## 滞后相关分析

`lag` 命令（HTTP 接口 `POST /lag-analysis`）在同一采样网格上比较两组读数，帮助研究人员区分共同趋势、真实滞后、缺测和并列值，而不是把一场集中降雨造成的巧合相关当成线索。分析结果只描述统计关联，不代表因果关系。

- 正滞后表示右侧数据晚于左侧，例如滞后 +1 用左侧格子与右侧下一个格子配对。
- 左右两侧各按自己的规则（来源、质量过滤、首选来源选择、`sum` 或 `mean` 聚合）落到同一网格；只比较双方都有效的格子，不补零、不向前填充。首选来源选择保证同一格子不会把多个来源重复计入。
- 每个滞后给出 Pearson、并列秩取平均的 Spearman、样本量和逐格排除原因（左侧缺测、右侧缺测、双方缺测）。常量序列或样本不足时标记为不可估计，不输出系数。
- 显著性使用保留块内顺序的块置换检验，`seed` 固定时结果可复算；一次分析内所有可估计滞后统一做 Holm 校正。
- 结果绑定观测版本（`sequence`、`head` 与请求指纹），每个配对都带格子时间和观测血缘（key、revision、batch），可以查回实际配对值。

请求示例：

```json
{
  "from": "2026-11-01T00:00:00Z",
  "until": "2026-11-01T08:00:00Z",
  "grid": {"widthMs": 3600000},
  "left": {"station": "plot1", "metric": "rainfall"},
  "right": {"station": "plot1", "metric": "soil_moisture"},
  "lags": [-1, 0, 1],
  "permutations": 499,
  "seed": 20261111
}
```

## 目录与数据

src/ 保存领域逻辑和请求入口，tests/ 包含正常行为、边界与恢复测试。例子中的标识和记录为合成资料，不包含真实人员或生产测量。业务目录和本地数据库由调用者指定，应与源码分开保存。

## 干净环境复现

容器定义固定运行时版本。构建时准备环境，运行时无需网络；每次启动会复制只读源码到临时工作目录，测试产生的文件不会写回仓库。

```sh
docker build -t local-product-check .
docker run --rm --network none local-product-check
```
